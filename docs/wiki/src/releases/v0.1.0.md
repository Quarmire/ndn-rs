# v0.1.0

ndn-rs is a Rust NDN forwarder and library stack. v0.1.0 marks the
end of the pre-release readiness program: a four-phase audit,
architecture cleanup, tiered-API split, and documentation rewrite
that together establish the public surface ndn-rs ships under
SemVer.

## What shipped

### Develop tier

For application authors. Single umbrella crate; `use ndn::Consumer;`
reads cleanly.

- `Consumer::fetch` / `fetch_object` (RDR-shaped segmented fetch).
- `Producer::publish_object` and `Responder` (closure-style).
- `Subscriber` (multi-publisher stream, read-only in v0.1.0).
- `KeyChain` with SQLite-backed and IndexedDB-backed PIBs.
- `IpcConnection` (external forwarder) and `InProcConnection`
  (embedded engine).
- `wasm32-unknown-unknown` target builds for the packet + security
  subset; the embedded engine path runs via `WasmEngineBuilder`.

### Extend tier

For protocol, strategy, and face authors. Trait surfaces stable
across v0.1.x.

- `Strategy` with `register_strategy!` macro and `schedule()` for
  timers.
- `RoutingProtocol` + `RoutingHandle` with typed
  `RoutingProtocolStatus`.
- `Face = Transport + LinkService` composition; default
  `LpLinkService` (NDNLPv2) and `PassthroughLinkService`.
- Twelve in-tree face transports (UDP, TCP, Unix, in-process,
  shared memory, Ethernet, WiFi direct, BLE, serial, WebSocket,
  WebTransport, WebRTC).
- `MgmtModule` + `MgmtRouter` with per-file modules for faces / FIB
  / RIB / strategy / CS / forwarder-status / routing / discovery /
  log / measurements / coding / rate-limit / security / service.
- `TrustPolicy` / `ValidationPolicy` with hierarchical, LVS, static,
  chained, accept-all impls.

### Instrument tier

For researchers and measurement tooling. Feature-gated
`experimental-instrument`.

- `ForwarderEngine::{fib,rib,pit,cs,strategy_table,measurements,routing,discovery_ctx}`
  table accessors.
- `TapFace`, `CallbackFace`, `InProcFace::new_kind` for
  wire-packet experiments.
- `ContextEnricher` for cross-layer enrichment.

### Forwarder and tooling

- `ndn-fwd` standalone forwarder binary; clean shutdown, restored
  pins, TLV management protocol on `/localhost/<forwarder>/...`.
- `ndn-ctl` operator CLI.
- `ndn-dashboard` Dioxus web app with local / external /
  multi-forwarder profiles.
- `enroll-ndncert` and `ndn-fwd-tokens` for NDNCERT issuance with
  invite tokens.
- `ndn-otel-bridge` OpenTelemetry bridge (NDN-native, no HTTP
  scraping).
- `ndn-bench` workload generator.
- `deploy/docker-compose.yml` + `install.sh` self-hosting stack.

### Spec compliance

- BLAKE3 signature types 6 / 7 registered.
- NDNCERT issued certs round-trip.
- LP TLV (NDNLPv2): nonce length, NACK reason, KeyLocator rules,
  URI / FinalBlockId conventions — all witnessed.
- Audit harness under `testbed/tests/audit/` with exit-code witnesses.

## Phase program

| Phase | Deliverable |
|---|---|
| 1 | Audit honesty pass (every finding re-verified on disk). |
| 2 | Architectural cleanup (20 ARCH items: ARCH-1 … ARCH-20). |
| 3 | Tiered API design (`ndn` umbrella, `fetch_object`, `experimental-instrument`). |
| 4 | Wiki rewrite — this documentation. |

Phase design notes are kept internally; the wiki surfaces what
shipped, not the working notes.
